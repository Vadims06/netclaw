# Tasks: Astra Live Digital Twin

**Input**: Design documents from `/specs/122-astra-live-digital-twin/`
**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/, loop.md

**Scope of this tasks.md — read loop.md first**: Per the Loop Contract, `/speckit.implement` for this
feature does **not** implement the Astra Live Digital Twin. It builds two things: (1) the frozen
back-pressure harness (plan.md Phase A/B — `mcp-servers/astra-twin-mcp/`, `models/twin_schema.py`,
`harness/`, `tests/contract/`), which must be real, working, and self-tested, not stubs; and (2) the
`loop/` scaffold itself. The remaining feature work — plan.md's Phase C (live HUD integration) and
Phase D (Astra Twin enrollment + constitution artifact coherence) — becomes `loop/IMPLEMENTATION_PLAN.md`,
the loop's own task queue, generated by T015 below, not executed here.

**Tests**: Contract tests for `models/twin_schema.py` and `astra-twin-mcp`'s tool responses are
explicitly required (frozen alongside the code they check) — this is a feature built by an unattended
loop; the tests exist to keep the loop honest, not as optional coverage.

## Phase 3: Frozen collector — `astra-twin-mcp` (plan.md Phase A)

- [x] T005 `mcp-servers/astra-twin-mcp/collector.py` — asyncio polling loop calling the *existing*
      pyATS MCP server's read-only tools on a fixed interval (default from research.md — configurable,
      not hardcoded), diffing against an in-memory last-known snapshot, producing `TwinDelta` objects
      per data-model.md's transition rules. No device credential, session, or write-capable tool call
      anywhere in this file (FR-003/FR-005/R4).
- [x] T006 `harness/assert_lab_only.py` — given a `PYATS_TESTBED` path, resolves the testbed and fails
      (non-zero exit) if any device in it is not on a lab allowlist. Called both by `ralph.sh`'s
      preflight and by `astra-twin-mcp/server.py` at its own startup (contracts/astra-twin-mcp.md
      "Required environment").
- [x] T007 `mcp-servers/astra-twin-mcp/server.py` — FastMCP server exposing `get_snapshot()`,
      `get_deltas(since_seq)`, `get_status()` exactly per contracts/astra-twin-mcp.md, including the
      documented failure modes (empty snapshot before first poll; buffer-overflow sentinel on stale
      `since_seq`). Calls `harness/assert_lab_only.py`'s check at startup and refuses to serve if it
      fails.
- [x] T008 [P] `tests/contract/test_astra_twin_mcp.py` — exercise all three tools against a fixture
      lab snapshot/delta sequence; assert the documented failure-mode behaviors specifically (this is
      what stops a future loop iteration from "fixing" an error case into a silent wrong answer).
- [x] T009 [P] `mcp-servers/astra-twin-mcp/README.md` — tool inventory, required environment
      (`PYATS_TESTBED`), transport (stdio), and the explicit "no write-capable tool" statement,
      satisfying constitution Principle XII/MCP Server Standards.

## Phase 4: Frozen verification harness (plan.md Phase B — must self-test before Phase 5)

- [x] T010 `harness/run_gates.sh` — runs, in order: Python build/import check, `pytest tests/contract`,

- [x] T011 `harness/visual_verify.py` (Playwright, research.md R2) — launches a headless browser

      `get_snapshot()` response.
- [x] T012 `harness/done_gate.sh` — passes only when every FR-001..FR-011 / SC-001..SC-006 in spec.md

      quickstart.md Phase B checkpoint asks a human to re-verify.
